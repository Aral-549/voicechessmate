The Problem

285 million people can't play
digital chess.

"Chess.com and Lichess are completely inaccessible to me.
Screen readers turn a chess board into an HTML table."
— Blind chess player, Reddit r/blind
  • Platforms require constant 2D visual tracking. Blitz and bullet games — with their clock pressure — are physically impossible for blind players.
  • Screen readers introduce 6–10 seconds of delay per move. One slow read and the clock flags. That's game over.
  • No tactical awareness. No voice feedback for checks, threats, forks, or pins. Just raw coordinate data with zero context.
Our Solution

Hold a key. Say your move.
That's the whole interface.

Typed Tool Calls

The AssemblyAI agent calls typed tools — apply_move, describe_board, undo_move, get_legal_moves. Chess is deterministic on our side; the AI handles the language.

Sub-300ms response

PCM16 streams in 25ms chunks. The board updates and sounds play before the coach finishes speaking.

The hard audio problem we solved

A single AudioContext at forced 24kHz gets silently muted by Linux PulseAudio. We solved it with dual contexts:

// Mic capture — 24kHz (AssemblyAI requires this) captureCtx = new AudioContext({ sampleRate: 24000 }) // Speaker — native rate (48kHz on most hardware) speakerCtx = new AudioContext() // → AudioBufferSourceNode auto-resamples

Built for Blind Chess

IBCA phonetic notation.
Because B, C, D, E, G all sound the same.

The International Blind Chess Association (1985) standardised phonetic file names specifically to prevent mishearing over audio. We implement this natively.

FileIBCA NameExample
aAnna"Pawn Anna 2 to Anna 4"
bBella"Knight Bella 1"
cCesar"Pawn Cesar 7 to Cesar 5"
dDavid"Queen David 5"
eEva"Pawn Eva 4"
fFelix"Knight to Felix 3"
gGustav"Bishop Gustav 2"
hHector"Rook Hector 8"

Spatial Audio Earcons

Each move plays a stereo-panned tone: file A is far-left, file H is far-right. Rank 1 is low pitch, rank 8 is high. Blind players hear direction as spatial audio.
